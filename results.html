Do 5% samples rank index configurations the way the full database does?

TPC-DS, PostgreSQL 14, scale factor 1. Thirty-three configurations, each a set of indexes, scored by the total runtime of all 99 queries. The same configurations were timed on 5% samples and compared to the full-database ranking.

5 to 6 October 2026. One seed. Per-query cap 20 seconds, counted as 20 seconds. Ground truth is a real CREATE INDEX and a measured time, not optimizer cost.

Where the workload time goes

No extra index takes 190.7 s. The best configuration, a small set of dimension filters, takes 172.9 s. The 17.8 s gap is the whole ranking.

Ranking agreement

Kendall tau-b between each reduced database and the first full-database run. The bar is a 95% bootstrap interval over the 33 configurations. The dashed line is a second full-database run scored against the first: that is the noise ceiling, tau 0.45.

How much cheaper the evaluation is

Hours to build every configuration's indexes and run all 99 queries, summed over the 33 configurations. Sample-build time is not included. The axis is logarithmic.

The configurations are close, and a second run moves them

Seconds of workload above the best configuration on the first full run. The dashed line at 5.3 s is the median amount by which the same configurations were slower the next morning.

Best configuration from each advisor

Fastest of that advisor's five configurations on the first full run. Workload seconds, axis starting at 170.

Numbers behind the figures

Score is query time only. Regret is the full-database time of the sample's pick, divided by the best full-database time. 1.000 means the sample picked the winner.
